# Spaceship Titanic

Решение домашнего задания №2 по курсу **ML Start 2026** на основе соревнования **Kaggle Spaceship Titanic**.

> **Задача:** бинарная классификация — предсказать, был ли пассажир перемещён (`Transported`) в другое измерение после пространственной аномалии.

**Kaggle Competition:** https://www.kaggle.com/competitions/spaceship-titanic

---

## 📌 Цель проекта

Цель работы — построить полноценный и понятный ML-пайплайн, последовательно улучшая решение:

**baseline → feature engineering → отбор признаков → подбор моделей → tuning → blending / stacking → final submission**

Основная метрика соревнования — **Accuracy**.

## Feature Engineering

Из исходных признаков были созданы дополнительные признаки.

### PassengerId
Из `PassengerId` извлечена информация о группе пассажира:
- `GroupSize` — размер группы
- `GroupMember` — номер пассажира внутри группы
- `IsSolo` — путешествует ли пассажир один

### Cabin
Признак `Cabin` разделён на:

- `CabinDeck`;
- `CabinNum`;
- `CabinSide`;
- `CabinRegion`.

### Name

Используется:
- `SurnameCount` — количество пассажиров с той же фамилией.
Это позволяет сохранить информацию о возможных семейных связях без использования самой фамилии как high-cardinality категориального признака.

### Расходы

На основе:

- `RoomService`;
- `FoodCourt`;
- `ShoppingMall`;
- `Spa`;
- `VRDeck`

созданы:

- `LogTotalSpend` — логарифм суммарных расходов;
- `NoSpend` — индикатор отсутствия расходов;
- `AmenitiesUsed` — количество типов услуг, которыми воспользовался пассажир.

### Возраст

Созданы возрастные группы `AgeGroup`.

## Корреляции и линейная зависимость

Отдельно проверяется разница между:

- высокой корреляцией;
- точной линейной зависимостью.

Например, `LogTotalSpend` и `NoSpend` могут быть сильно отрицательно коррелированы, но это не означает, что один признак является точной линейной комбинацией другого
После preprocessing дополнительно проверяется ранг матрицы признаков.

## Baseline и первые улучшения

Сначала были обучены простые baseline-модели на исходных признаках.

После этого был добавлен Feature Engineering и проведено повторное сравнение.

На первом этапе Feature Engineering дал заметное улучшение качества LightGBM по сравнению с моделью на исходных данных.

Пример промежуточного результата:

| Эксперимент | CV Accuracy |
|---|---:|
| Logistic Regression на исходных признаках | ≈ 0.786 |
| LightGBM на исходных признаках | ≈ 0.792 |
| LightGBM + Feature Engineering | ≈ 0.807 |

Это подтвердило, что новые признаки содержат полезную дополнительную информацию.

## 🎯 Feature Importance и отбор признаков

Для оценки важности используются два подхода:

1. встроенный `feature_importances_` у LightGBM;
2. `permutation_importance`.

После этого признаки сортируются по важности.

Далее реализован последовательный перебор:

1. берём несколько самых важных признаков;
2. добавляем по одному;
3. для каждого количества считаем CV Accuracy;
4. выбираем количество признаков, при котором качество максимально.

Таким образом отбор признаков основан не только на importance, но и на реальном изменении качества модели.

##  Ансамбли

В работе реализованы два способа ансамблирования.

### Weighted Blending

Для нескольких лучших моделей:

- строятся OOF-предсказания;
- перебираются веса моделей;
- подбирается threshold;
- выбирается комбинация с лучшей OOF Accuracy.

### Stacking

Первый уровень:

- Logistic Regression;
- LightGBM;
- XGBoost;
- CatBoost.

Второй уровень:

- Logistic Regression.

Мета-модель обучается на OOF-предсказаниях базовых моделей.

---

## Защита от Data Leakage

В работе соблюдаются основные правила:

- целевая переменная `Transported` не участвует в Feature Engineering;
- preprocessing выполняется внутри `Pipeline`;
- импутация и One-Hot Encoding обучаются отдельно внутри каждого CV-фолда;
- используется `StratifiedKFold`;
- test не участвует в подборе гиперпараметров;
- ансамбли строятся на OOF-предсказаниях.
